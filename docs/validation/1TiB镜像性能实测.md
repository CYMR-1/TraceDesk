# 1 TiB 镜像与大清单性能实测

2026-11-19，在 Windows、项目虚拟环境和随项目分发的 Sleuth Kit 4.15.0 上测试。使用临时案件，没有修改原始样本。界面首屏从触发“加载镜像”计时，到后台任务完成、首个目录已显示并可操作为止，文件选择器由测试直接提供路径。

| 测试镜像 | 操作 | 本机耗时 |
| --- | --- | ---: |
| 1 TiB 稀疏 RAW，整个卷为 FAT32 | 打开到根目录，3 次中位数 | 0.21 秒 |
| 同一 FAT32 卷 | 递归读取目录、映射空余簇并保存索引，3 次中位数 | 0.44 秒 |
| 1 TiB 稀疏 RAW，FAT16 分区放在末端 | 打开子目录 / 预览小文件首页，分别取 3 次中位数 | 0.08 / 0.03 秒 |
| 同一 FAT16 分区 | 搜索一个小文件 / 导出 / 与导出副本比对，分别取 3 次中位数 | 0.05 / 0.06 / 0.04 秒 |
| 50 GiB 分段 E01，含 3 个 NTFS 分区 | 打开到首个根目录 | 0.58 秒 |
| 同一 E01 | 首次读取主 NTFS 分区根目录 / Windows 目录，含两种分配状态 | 2.71 / 2.75 秒 |
| 同一 E01，4,704,752 字节的文件 | 限定文件检索前 2 个匹配 / 导出 / 字节流摘要比对 | 0.14 / 0.22 / 0.32 秒 |
| 同一 E01 | 完整读取逻辑介质并计算全部 15 个物理分段的 SHA-256 | 125.29 秒 |
| 同一 E01，封装共 16,065,168,064 字节 | 随后重读所有分段并检查各段摘要，缓存已预热 | 4.01 秒 |
| 同一 E01 | 递归扫描并保存 532,431 条记录，含删除记录 | 81.82 秒 |
| 同一清单 | 建立并排序 2,123,388 个 MACB 事件的时间线索引 | 0.68 秒 |
| 同一 E01 | 当前会话完成固定后生成 Markdown 报告 | 约 0.08 秒 |

FAT32 夹具使用 512 字节扇区、32 KiB 簇。一个 10 MiB 文件占用卷末端的 320 个簇，从首页直接跳到末页读出了预置标记，完整索引中的未分配字节数也与布局相符。另一个夹具验证了高分区偏移下的路径、搜索命中字节和导出内容。稀疏镜像只有少量实际写入的数据，没有测量写满 1 TiB 的磁盘做整盘哈希或穷举内容搜索的耗时。

E01 的完整逻辑摘要及全部物理分段摘要与既有独立测试记录一致。对一个超过 12 MiB 的 NTFS 属性流，从原生读取器定位末尾 4 KiB，逐字节比对了 TSK 导出的相同范围。上表的完整索引和时间线耗时涵盖数据构建，未计入另行构建 Qt 文件树的耗时。所测文件数量、缓存、磁盘、压缩率和并行负载都会影响读数。

## 复测

在项目目录执行下列命令。容量夹具需要支持稀疏文件的测试卷，创建成功后才会写入高偏移位置。E01 实测使用本机课程样本，未将样本或案件纳入仓库。

~~~powershell
.\.venv\Scripts\python.exe -m unittest tests.ui.test_large_images -v
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
~~~

大镜像回归覆盖高偏移、文件末页、按目录读取、正式与初步记录、整案检索、索引取消重试、哈希取消与重新打开案件，以及时间线跨页序号。
