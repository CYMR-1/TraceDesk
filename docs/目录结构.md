# 目录结构与维护指南

## 总体结构

根目录保留 Cargo 工作区配置、一键启动脚本与项目说明。应用全面基于 **Rust + Tauri 2 + React/TypeScript** 构建，按底层只读引擎、案件核心业务、MCP 服务端、CLI 工具、Tauri 2 桌面宿主和前端工作台分层解耦；演示输入、案件输出、官方 TSK 工具与本地构建产物各有独立目录。

## 增删功能

桌面工作台默认启用 11 个可装配功能模块（集中登记在 `frontend/src/features/registry.ts`）：基础工作流由 `cases`、`evidence`、`files` 组成；`export`、`file_tools`、`report`、`timeline`、`audit`、`help`、`mcp`、`review` 可按需启停。

- **停用**：在 `frontend/src/features/registry.ts` 的默认启用列表中移除对应功能标识，重新构建前端即可同步隐藏对应按钮、导航标签与面板，不影响底层案件持久化与审计链记录。
- **新增模块**：在 `frontend/src/modules/` 新增页面或对话框组件，在 `frontend/src/features/registry.ts` 中注册模块元信息；若需新的 Rust 后端能力，在 `crates/tracedesk-core/src/` 实现纯业务接口后，于 `src-tauri/src/commands.rs` 与 `src-tauri/src/lib.rs` 注册 Tauri Command，并在 `frontend/src/types/ipc.ts`、`frontend/src/api/tauri.ts` 补齐类型与调用封装。
- **扩展 MCP 工具**：在 `crates/tracedesk-mcp/src/service.rs` 与 `tools.rs` 中新增工具定义与编排逻辑，桌面端内嵌 HTTP MCP 服务（`src-tauri/src/mcp_http.rs`）与独立 `tracedesk-mcp.exe` 共享同一 `McpServer`，无需重复实现。

| 维护任务 | 主要入口 | 对应验证 |
| --- | --- | --- |
| 底层 TSK、EWF、FAT、NTFS 与随机读取 | `crates/tracedesk-engines/src/`（`tsk.rs`、`ewf.rs`、`fat.rs`、`ntfs.rs`、`volume.rs`、`hash.rs`、`win.rs`） | `cargo test -p tracedesk-engines` |
| 案件保存、审计链、覆盖评估、报告与复核包 | `crates/tracedesk-core/src/`（`case.rs`、`coverage.rs`、`reporting.rs`、`review.rs`、`formatting.rs`） | `cargo test -p tracedesk-core` |
| 内容搜索（SIMD + Rayon）、时间线、预览与取证发现 | `crates/tracedesk-core/src/`（`content_search.rs`、`timeline.rs`、`preview.rs`、`file_tools.rs`、`findings.rs`、`browser_index.rs`） | `cargo test -p tracedesk-core` |
| 标准 MCP 服务端（19 工具、stdio / Streamable HTTP） | `crates/tracedesk-mcp/src/`（`tools.rs`、`service.rs`、`stdio.rs`、`http.rs`、`runtime.rs`） | `cargo test -p tracedesk-mcp` |

| Tauri 2 桌面宿主、38 项 IPC、读写分离缓存与内嵌 HTTP MCP | `src-tauri/src/`（`lib.rs`、`state.rs`、`commands.rs`、`mcp_http.rs`） | `cargo test -p tracedesk-desktop` |

依赖方向严格分层：`frontend/` → `src-tauri/`（桌面宿主） / `tracedesk-mcp` / `tracedesk-cli` → `tracedesk-core` → `tracedesk-engines`。核心库、引擎库与独立 MCP 服务端零前端/Tauri 依赖，可独立编译与自动化测试。

## 数据与生成文件

- `evidence/` 是输入目录。仅跟踪自建的两份 FAT16 演示镜像及其哈希清单（共 4 个文件）；用户自行放入的镜像保持在本地，不自动入库。
- `cases/` 是案件输出目录。每个案件独立包含 `case.json`、`audit.jsonl`、`audit.head`、`case.lock`、`exports/`（导出副本、`同名副本-*` 子目录与 `取证发现汇总_*.md`）和 `reports/`（Markdown 报告、`search_*.json`、`fsstat-*.txt`、复核包 `.zip` 及 `.zip.sha256`；非空清单另含 `inventory-*.jsonl.gz`）。源码仓库仅保留 `cases/.gitkeep`。
- `logs/` 按需保存运行日志与最近演示案件路径；`target/` 与 `frontend/dist/`、`frontend/node_modules/` 为本地编译与依赖缓存，均不入库。
- `tools/` 中的官方 Sleuth Kit 4.15.0 发行结构不可拆分；分发时需保留完整 DLL 与 `licenses/`。

## 常用命令

在项目根目录（PowerShell）执行：

```powershell
# 构建前端生产资源
Set-Location frontend; npm.cmd ci; npm.cmd run build; Set-Location ..

# Release 全量编译（生成 desktop / mcp / cli 三大原生二进制）
cargo build --release --workspace

# 静态检查（零警告门禁）与全工作区自动化测试
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace

# 启动原生桌面工作台（也可直接双击 启动取证工作台.bat）
.\target\release\tracedesk-desktop.exe

# CLI：运行端到端演示闭环 / 生成演示镜像 / 核验复核包 / 性能基准测试
.\target\release\tracedesk-cli.exe run-demo
.\target\release\tracedesk-cli.exe make-demo
.\target\release\tracedesk-cli.exe verify-bundle "复核包路径.zip" --sha256 独立取得的64位摘要
.\target\release\tracedesk-cli.exe bench

# MCP 服务端：stdio 模式（默认）与本机回环 Streamable HTTP 模式
.\target\release\tracedesk-mcp.exe --transport stdio
.\target\release\tracedesk-mcp.exe --transport streamable-http --host 127.0.0.1 --port 8765 --path /mcp
```

新增或删除源码/文档文件时，需同步维护本文目录树（注意按项目约定不展开 `docs/validation/`、`evidence/`、`tools/` 的下一级文件）。
