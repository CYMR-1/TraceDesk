# 目录结构与维护指南

## 总体结构

根目录保留启动入口与依赖配置。源码按案件业务、底层引擎和界面分组；演示输入、案件输出、第三方工具和本地生成文件各有独立位置。

```text
TraceDesk/
├─ main.py                         # Python 入口
├─ 启动取证工作台.bat               # 创建/使用项目 .venv 后启动
├─ requirements.txt                # Python 第三方依赖
├─ README.md                       # 项目首页、安装和操作流程
├─ .gitignore                      # 本地数据与缓存忽略规则
├─ forensic/                       # 应用源码包
│  ├─ __init__.py
│  ├─ launcher.py                  # 启动器、异常报告
│  ├─ paths.py                     # 项目根目录、图标和运行目录定位
│  ├─ core/                        # 不依赖 Qt 的业务与任务调度
│  │  ├─ case.py                   # 案件、哈希、审计、导出、报告
│  │  └─ tasks.py                  # 后台任务、结果队列
│  ├─ engines/                     # 底层只读工具与文件系统分析
│  │  ├─ tsk.py                    # mmls/fsstat/fls/icat 适配
│  │  └─ fat.py                    # FAT 表、簇分配与空间区域
│  ├─ ui/                          # PySide6 界面
│  │  ├─ controller.py             # 用户操作、案件服务、后台任务协调
│  │  ├─ workspace.py              # 主窗口、顶部导航与案件工具
│  │  ├─ browser.py                # 完整文件树、目录列表、筛选联动
│  │  ├─ preview.py                # 按页读取和文本/十六进制显示
│  │  ├─ views.py                  # 案件对话框、只读文本面板
│  │  ├─ appearance.py             # 白灰主题、字体、DPI 与窗口尺寸
│  │  └─ branding.py               # 图标加载和 Windows 任务栏身份
│  └─ assets/                      # 图标源文件及生成资源
│     ├─ tracedesk.svg
│     ├─ tracedesk.png
│     └─ tracedesk.ico
├─ scripts/                        # 可直接运行的开发辅助命令
│  ├─ install_tsk.ps1              # 安装/校验 TSK
│  ├─ make_demo.py                 # 生成两份演示镜像及哈希清单
│  ├─ run_demo.py                  # 完整演示流程，--gui 打开案件
│  ├─ make_icon.py                 # SVG → PNG / ICO
│  └─ package.py                   # 构建可分发源码工程包
├─ tests/                          # 与源码职责对应的回归测试
│  ├─ core/                        # 案件流程、全分区扫描、后台任务
│  ├─ ui/                          # Qt 控件、自动加载、目录树、真实文件预览
│  ├─ fixtures.py                 # 多分区测试镜像夹具
│  ├─ test_launcher.py             # 启动异常与日志
│  └─ test_project_layout.py       # 异目录资源定位和打包内容
├─ docs/                           # 文档入口：docs/README.md
│  ├─ README.md
│  ├─ 目录结构.md                  # 本文，目录职责的唯一完整清单
│  ├─ 设计与验收说明.md
│  ├─ ui/                          # 设计预览、实施说明和真实截图
│  ├─ ui-redesign/                 # 历史聊天预览的兼容文件
│  └─ validation/                  # test-results.txt 等验证记录
├─ evidence/                       # 演示镜像和本地源证据
│  ├─ demo.dd                      # 带分区表的 FAT16 示例
│  ├─ demo.manifest.json
│  ├─ demo_volume.dd               # 偏移 0 的 FAT16 示例
│  └─ demo_volume.manifest.json
├─ tools/sleuthkit-4.15.0-win32/    # 官方发行包；保留 DLL 和 licenses
├─ cases/                          # 运行生成的案件库
├─ logs/                           # 运行生成的日志、最近演示路径
├─ dist/                           # 打包输出
├─ .test-work/                     # 测试临时案件、检查输出
└─ .venv/                          # 项目 Python 虚拟环境
```

各 Python 子包都有 `__init__.py`。`.git/` 是版本库，`AGENTS.md` 是本地协作约定，二者不作为产品文件分发。

界面预览的维护源为 `docs/ui/tracedesk-preview.html`。`docs/ui-redesign/tracedesk-preview.html` 保留相同内容，供历史聊天中的内联预览读取；更新预览时同步复制到此兼容路径，避免旧引用报文件不存在。

## 按任务查找代码

| 维护任务 | 主要入口 | 对应验证 |
| --- | --- | --- |
| 调整布局、目录树和筛选 | `forensic/ui/workspace.py`、`browser.py` | `tests/ui/test_gui.py` |
| 修改配色、字体、图标 | `forensic/ui/appearance.py`、`branding.py`、`forensic/assets/` | 实际窗口检查、`test_project_layout.py` |
| 修改文字/十六进制预览 | `forensic/ui/preview.py` | `tests/ui/test_preview.py` |
| 调整操作流程 | `forensic/ui/controller.py` | 界面测试和实际演示 |
| 修改案件保存、审计、导出或报告 | `forensic/core/case.py` | `tests/core/test_workflow.py` |
| 调整任务调度 | `forensic/core/tasks.py` | `tests/core/test_tasks.py` |
| 调整镜像解析 | `forensic/engines/tsk.py`、`fat.py` | 真实 TSK 工作流测试 |
| 修改资源路径或分发内容 | `forensic/paths.py`、`scripts/package.py` | `tests/test_project_layout.py`、解压包启动 |

依赖方向为入口 → 界面控制器 → 案件业务 → 引擎适配；预览视图直接通过只读 TSK 接口读取字节。业务和引擎模块不导入 Qt。共用资源路径从 `forensic.paths` 导入，不在搬动后的模块中推算 `__file__.parent.parent`。脚本入口可用自己的位置将项目根目录加入导入路径。

## 数据与生成文件

- `evidence/` 是输入。只跟踪并打包上述四个自建演示文件；用户自行加入的镜像保持在本地，不自动进入 Git 或源码包。现有镜像文件没有搬动，已记录的案件路径继续有效。
- `cases/` 是输出。每个案件独立包含 `case.json`、`audit.jsonl`、`audit.head`、`case.lock`、`exports/` 和 `reports/`。源码包只保留 `cases/.gitkeep`。
- `logs/startup.log` 保存错误信息；`logs/latest-demo.txt` 保存最近一次演示案件位置。
- `dist/`、`.test-work/`、`.venv/`、`__pycache__/` 和运行案件不入库、不打包。整理目录不会清空已有案件、证据或本地环境。
- `tools/` 中的官方发行结构不拆分；程序运行依赖完整的 DLL，分发还需保留许可证。

## 常用命令

在项目根目录执行。使用 Python 前先创建 `.venv`，第三方依赖仅安装到该虚拟环境。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r requirements.txt
.\.venv\Scripts\python.exe main.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_gui.py -v
.\.venv\Scripts\python.exe scripts/run_demo.py --gui
.\.venv\Scripts\python.exe scripts/make_icon.py
.\.venv\Scripts\python.exe scripts/package.py
```

新增模块放到对应职责目录，新增测试放到相应测试子包。更新目录时同步检查 Python 导入、测试补丁路径、`paths.py`、文档链接和解压后的工程包；目录清单集中更新本文，避免多处复制后失效。
